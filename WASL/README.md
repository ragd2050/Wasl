# WASL — منصة التقييم المبدئي للنطق واللغة

نسخة العرض النهائية للمشروع، جاهزة للنشر على **Vercel** كموقع ثابت.

يعرض الموقع رحلة متكاملة لحالة افتراضية تبدأ من موعد الطفل، ثم التحقق والاستبيان
وفحص السمع وتسجيل الصوت، وتنتهي بفرز أولي وأولوية مقترحة ومراجعة المختص ثم رحلة
الحجز. تسجيل الصوت داخل المتصفح حقيقي، بينما نتيجة التحليل والأولوية والمؤشرات
محاكاة ثابتة ومعدة مسبقًا لتوضيح فكرة النظام بصورة مستقرة أثناء العرض.

## تجربة العرض المقترحة

1. افتح الصفحة الرئيسية وسجّل الدخول.
2. من **مواعيد اليوم** افتح حالة سارة عبدالله العتيبي عند الساعة 09:45.
3. أكمل خطوات الحالة والاستبيان وفحص السمع.
4. سجّل عينة صوتية أو ارفع ملفًا صوتيًا.
5. أرسل التقييم لمشاهدة مراحل التحليل المحاكى.
6. افتح بوابة المختص لمراجعة المؤشرات والأولوية والخطة المقترحة.
7. اعتمد النتيجة وأكمل رحلة ولي الأمر والحجز.

> النتيجة المعروضة فرز أولي محاكى وليست تشخيصًا طبيًا، ولا تعتمد على محتوى
> التسجيل. القرار السريري النهائي يجب أن يصدر من أخصائي نطق ولغة مؤهل.

## التشغيل محليًا

لا يحتاج عرض Vercel إلى Python أو تثبيت مكتبات. من داخل مجلد المشروع شغّل:

```powershell
py -m http.server 8080
```

ثم افتح:

```text
http://127.0.0.1:8080/
```

يمكن أيضًا النقر مرتين على `START-WASL.bat` لتشغيل النسخة المحلية الموسعة، لكن
هذا غير مطلوب للنشر على Vercel.

## الرفع إلى GitHub

```bash
git init
git add .
git commit -m "Initial WASL Vercel release"
git branch -M main
git remote add origin https://github.com/USERNAME/wasl.git
git push -u origin main
```

## النشر على Vercel

1. افتح Vercel واختر **Add New → Project**.
2. استورد مستودع GitHub الخاص بالمشروع.
3. اترك **Framework Preset** على `Other`.
4. اترك **Build Command** فارغًا.
5. اجعل **Output Directory** هو `.` أو اتركه فارغًا.
6. اضغط **Deploy**.

ملف `vercel.json` مرفق، ولا يحتاج المشروع إلى متغيرات بيئة أو قاعدة بيانات في
نسخة العرض الحالية. ويستبعد `.vercelignore` ملفات خادم Python من عملية النشر.

## أهم الملفات

- `index.html`: تسجيل الدخول وبداية الرحلة.
- `dashboard.html`: مواعيد اليوم.
- `case-intake.html`: بدء الحالة الافتراضية.
- `audio.html`: مهام التسجيل الصوتي.
- `ai-processing.html`: مراحل التحليل المحاكى.
- `specialist-cases.html`: قائمة حالات المختص.
- `clinical-review.html`: مراجعة المؤشرات واعتماد النتيجة.
- `guardian-report.html`: ملخص ولي الأمر.
- `sehhaty.html`: رحلة اختيار المنشأة والموعد.
- `assets/wasl-sim.js`: منطق محاكاة التحليل.
- `assets/sim-cases.js`: بيانات الحالات والنتائج المعدة للعرض.

## الخصوصية وحدود الاستخدام

- لا تستخدم بيانات مرضى حقيقية في نسخة العرض العامة.
- التسجيلات تحفظ مؤقتًا داخل متصفح المستخدم عبر IndexedDB ولا ترفع إلى Vercel.
- لا تعرض نتيجة المحاكاة على أنها تشخيص أو نتيجة نموذج طبي حقيقي.
- تكاملات نفاذ وصحتي والحجز في هذه النسخة واجهات عرض وليست اتصالات حكومية فعلية.
- قبل أي استخدام سريري فعلي يلزم باك-إند آمن، موافقة صريحة، سياسات احتفاظ وحذف،
  تحقق سريري مستقل، وضوابط وصول وتدقيق مناسبة.

للمزيد راجع `DEMO-SIMULATION-AR.md` و`SIMULATED-VS-REAL.md` و`TEST-REPORT.md`.
